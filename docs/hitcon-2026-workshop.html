The work being automated

Every alert costs an analyst the same four questions.

Who owns this host? Has this address appeared before? Is this the user's own VPN egress? Was there an MFA push?

The queue length isn't the pain. Re-deriving the same context, from scratch, per alert is the pain.

The second problem, which nobody writes about

No leaderboard tells you which local model can do this.

  • Benchmarks measure reasoning, coding, trivia — not "does it escalate benign Windows logons"
  • The failures are per alert class, and they invert between models
  • Nothing published tells you what a model costs in RAM at the context you need

So we had to measure it ourselves. That measurement is most of this talk.

Hypothesis

The bet

Constrain the model. Don't scale it.

A small local model, inside a deterministic state graph, answering one narrow schema-constrained question at a time — should beat a larger model given freedom.

The model never picks a tool, never chooses the next step, never sees a transcript of its own earlier output.

Three things we assumed, and then tested

All three turned out to be wrong.

Bigger is better

Assumed scaling up would improve everything.

More reasoning is better

Assumed a higher effort setting was a free upgrade.

A screening run predicts the real one

Assumed a cheap n=4 pass would rank models correctly.

Section 5 pays these off

Each was refuted by measurement, and the reasoning one was refuted in the dangerous direction.

05

Learnings

Material available to expand into
  • GGUF vs MLX — same weights, one silently ignores your schema
  • The harness completes an investigation with no working model at all — and scores like a cautious one
  • Models fail by cluster, and the clusters invert between models
  • Screen-stage ranking moved 28 points at real sample size
  • Don't derive tok/s from Ollama's usage — off by 8×
  • Docker binds single files by inode; git rewrites break the mount silently

Learning 1 · the counterintuitive one

More reasoning made it worse, in the dangerous direction.

gpt-oss:20b, same model, low against default effort, n=71:

metric@low@default
benign escalation45%58%
severity distance0.390.63
needle recall80%80%
false-positive control0/6 correct6/6 wrong

The VPN egress is a real anomaly — reason about it long enough and you argue yourself into flagging it. Three independent models show the same inversion.

Learning 2 · the deployment one

KV cache, not weights, decides what fits on your laptop.

modelMB per 1K ctxmax context under 17.5 GiB
gpt-oss:120b2.0does not fit
gemma4:12b6.5262,144
qwen3.6:27b69.232,768
mistral-small3.2167.98,192

84× spread, uncorrelated with model size. Quantisation shrinks weights but leaves KV identical — q4 and q8 of the same model measure exactly 69.2 MB/1K.

And the default will surprise you

Ollama sizes KV from the model's default context. qwen3.6:27b is 36.5 GB at default and 16 GB at num_ctx=8192. Invisible on a 128 GB Studio. Decisive on a laptop.

Learning 3 · the measurement one

Every footprint we published was 7.7% too heavy.

ollama ps prints decimal GB. The parser multiplied by 1024³. Every number in the project was wrong by the same constant.

Why it survived

It cleared a full gate, a 16-configuration sweep and two writeups — because a uniform multiplier reorders nothing. Every ranking was still correct. It eliminated one model for the wrong reason.

It surfaced only because a different number looked impossible: a 120B model reporting a KV cost of exactly 0.0 MB/1K, flat across three rungs.

Chase the implausible reading. The systematic error is underneath it.

Conclusions

What we'd tell you to do

Four things, all measured.

  • Constrain before you scale. The harness carries the structure; extra model capacity mostly buys room to argue away the grounded answer.
  • Use low reasoning effort wherever the model honours it — and verify it honours it by counting reasoning characters, not by checking the request didn't error.
  • Size by KV at your real context, not by download size. Bake num_ctx into a Modelfile variant; per-request doesn't survive.
  • Measure on your own alert classes. Failures cluster, and clusters invert between models. A leaderboard position does not transfer.

Position

It builds the hypothesis. You still make the call.

Strictly read-only. No remediation tool is wired to the model — not disabled, not present.
