The catch

It is wrong. By minute 60 you will know exactly why — and it is not because the model is small.

The actual pain

Alert fatigue isn't only volume. It's re-deriving the same context, alert after alert.

Who owns this host? Has this IP appeared before? Is this user's VPN egress? Was there an MFA push?

Every analyst answers those same four questions from scratch, every time. That is the time sink — not the size of the queue.

Why not cloud

Three reasons, and only one of them is money.

Your logs are the payload

Alert triage means sending hostnames, usernames, internal IPs and raw log lines to the model. That is exactly the data you are not allowed to paste into a chat box.

Per-token pricing punishes the loop

Six LLM calls per alert. Multiply by your queue, then by every re-run while you tune the prompts.

It works on a mountain

No egress, no API key, no rate limit, no vendor deprecating your model mid-quarter.

Position

This builds the hypothesis. You still make the call.

It is strictly read-only. There is no remediation tool wired to the model — not disabled, not present. The only output is a report.

Say this out loud

We are not claiming an autonomous SOC. We will show you exactly what stands between here and there, with file names.

Yam

SIEM, briefly

A SIEM is a log pile with a query engine and a rule engine bolted on.

Agents ship logs. Decoders parse them into fields. Rules match fields and fire alerts with a severity. Alerts land in a searchable index. That is the whole idea.

Everything our agent does is: read that index, ask it follow-up questions, write a report. No SIEM-specific magic.

Yam

Why Wazuh for a workshop

Free, self-hosted, and it runs in Docker on your laptop.

  • Open source, no license, no trial clock
  • Two backends we actually use: the indexer (OpenSearch — alert corpus and search) and the manager API (agent and rule metadata)
  • Real decoders and rules you can break and fix in front of an audience
Caveat

Two backends means two auth strategies — HTTP Basic for the indexer, JWT for the manager. One connector, two clients inside it.

Yam

Portability

What would it take to point this at a different SIEM?

class SIEMConnector(Protocol):
    def health_check(self) -> bool: ...
    def pull_alerts(self, since, until, limit) -> list[RawAlert]: ...
    def search(self, query: SearchQuery) -> SearchResult: ...
    def get_agent_context(self, agent_id) -> AgentContext: ...
    def get_rule_metadata(self, rule_id) -> RuleMetadata: ...

Five methods. SearchQuery is a constrained object — field, operator from a fixed enum, value, time range — never a raw query string, so any backend can satisfy it.

04

The harness

16 minutes · Tommy

Start with what went wrong

Three things a small local model does that break naive agent designs.

It hallucinates confidently

Ask for an IP address and you get something IP-shaped that was never in the log.

It cannot juggle tools

Give it five tools and a goal and it picks wrong, or loops. Free-form ReAct is not available to us at this size.

Alert shape changes everything

An SSH brute force and a Mimecast email alert want completely different questions asked. One generic prompt serves neither.

So the design rule became: the model never decides what happens next.

The shape

Nine steps, fixed order, six LLM calls.

The mechanism that makes it safe

The model proposes. Code decides what survives.

Guardrails

Four rules, applied to all six calls.

  • Closed vocabulary everywhere a choice is made. Severity, confidence, pattern type, recommended actions — all enums. Two deliberate exceptions, both prose, both grounded.
  • Narrow input windows. Only step 2 sees the raw log. Everything after sees typed findings — never the raw alert again, never a transcript of earlier model output.
  • Validate or fall back. Schema failure retries once with the error appended, then takes a safe default and marks the report NEEDS_HUMAN_REVIEW. No unbounded retries.
  • Self-check is a re-read, not a continuation. Step 8 gets a fresh prompt with the same findings — never step 7's reasoning — so it cannot rubber-stamp itself.

The obvious question

If code decides everything, in what sense is this agentic?

Fair. Here is the honest boundary.

It is

It chooses which follow-up query to run from a menu, decides whether one is needed at all, judges what pattern the evidence shows, and audits its own draft against the findings. Those are judgement calls, made per alert, that change what happens next.

It isn't

It has no goal loop, no tool selection, no ability to take an action, and no way to change the order of the nine steps. If "agentic" means the model drives control flow — then no, deliberately.

We think that trade is correct at this model size. Ask us at the end whether a 70B changes it.

06

Where it breaks

8 minutes · Tommy · the payoff

Back to the cold open

The agent escalated mrahman. Here is what it never saw.

  • mrahman's own ocserv VPN connect, four minutes earlier
  • 100.72.44.19 assigned to him as NAT egress — the exact address that looked foreign
  • An MFA push, approved

Eight correlated alerts. All in the index. All retrieved. None of them reached the model.

The actual bug

Context gathered, reduced to a scalar, substance discarded.

The lesson we actually want you to take home

"The model was too small" is the wrong diagnosis nine times out of ten.

A bigger model would have escalated this too. It had nothing to reason from.

Generalise it

When your local agent gets something wrong, check what actually reached the prompt before you reach for more parameters. Log the rendered prompt. Read it. It is almost never what you assumed.

And the self-check didn't save us

Zero of thirteen claims flagged.

0/13Claims flagged · false positive run
0/9Claims flagged · true positive run
236sCost of the 13-claim audit

Step 8 audits each claim against the same findings step 7 saw. Both saw evidence_count: 8. Both concluded the same thing. An audit against the same impoverished input cannot catch an impoverished input.

So

It builds the hypothesis. You make the call.

The most expensive part of tier-1 work is assembling the picture — pulling the VPN log, checking the MFA push, finding out whose laptop this is. That is what got automated.

The judgement did not, and on this evidence it should not.

07

Lessons

10 minutes · Yam

Yam

The trap

Same weights. Same name. One silently ignores your schema.

Yam

Why this is worse than a crash

Nothing tells you. Every report just quietly says "needs human review".

  • The model is pulled, reachable, and answers unconstrained prompts fine
  • model_available() returns true — it only checks the model exists, not that it is usable
  • The retry-once mechanism gives zero protection: the failure is deterministic, not flaky
  • Every alert degrades to a stub report with none of the real analysis, forever

If you take one command home from this workshop, take the next slide.

Yam

Take this home

Before you trust any model with structured output, gate it.

Build before 21 Aug

Go/no-go smoke test script. Point it at a model, get back usable / not usable plus latency per schema shape — flat, multi-enum, nested list. This is the take-home artifact and the fallback-model answer in Act 2.

Not a leaderboard. A binary gate. "Can I build on this at all?" is the question nobody publishes an answer to.

Self-check dominates and scales badly. 9 claims took 71s; 13 took 236s. Claim count is driven by how many actions the draft selects from a 16-member catalog — so a chattier draft is quadratically more expensive to audit.

Yam

Observability, minimum viable

Two things we wish we had logged from day one.

The rendered prompt

Not the template — the final string. The evidence_count: 8 bug was invisible for weeks because everyone read the template and assumed.

Per-step wall clock

An SDK default of max_retries=2 was tripling every timeout. A 120s budget was costing 361s while the client believed it had made one attempt. Only per-step timing exposed it.

Every step appends to a timeline on the report — including skipped steps, with the reason. The whole run is reconstructable after the fact.
